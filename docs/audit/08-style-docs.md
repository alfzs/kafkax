## С2 [СЕРЬЁЗНО] `doc.go` определяет `skipped` как «оффсет отмечается», код выдаёт его и там, где не отмечается

**Статус: закрыто частично.** `doc.go` теперь прямо разводит два разных `skipped` и предупреждает,
что под отменённый контекст записей в DLQ нет. Отдельное значение `"cancelled"` остаётся волне 2 —
[03](03-observability.md) У3.

`doc.go:44-48` против `consumer.go:598-604`. При отмене контекста во время паузы между повторами код
пишет `consumerStatusSkipped` и выходит **без** `MarkCommitRecords`. `doc.go:88-90` этот случай
описывает, но статус метрики для него не называет — читатель остаётся с определением из строки 46.

Значение конфлатит «ушло в DLQ, закоммичено» и «не обработано, приедет снова».

**Чем грозит.** Дежурный при всплеске `skipped` на деплое будет искать записи в DLQ, которых нет.

**Исправление.** Либо дописать в `doc.go:88-90`, либо ввести четвёртое значение `"cancelled"` —
что предпочтительнее, см. [03-observability.md](03-observability.md) У3. Исправлять вместе.

## С3 [СЕРЬЁЗНО] Комментарий к `consumerStatusSkipped` описывает не тот случай, что в коде

**Статус: закрыто волной 1.**

`consumer.go:93-95`. Комментарий: «на топик нет обработчика либо отмена контекста прервала паузу».

1. Ветка «нет обработчика» (`consumer.go:582-591`) считает сообщение как `consumerStatusError` и
   травит партицию — комментарий прямо противоречит коду в 490 строках ниже.
2. Основной и штатный источник `skipped` — `resolveFailure` (`:665`), где вердикт как раз **был** и
   он отрицательный, а `OnMessageSkipped` забрал сообщение. В комментарии не упомянут вовсе.

**Чем грозит.** Сопровождающий, доверившись комментарию, будет искать причину роста `skipped` в
незарегистрированных обработчиках вместо DLQ-хука.

## У2 [УМЕРЕННО] Ограничение `HeartbeatInterval ≤ SessionTimeout/3` заявлено, но не проверяется

**Статус: закрыто волной 1.** Проверка сравнивает с третью `SessionTimeout`, ровно как обещает
godoc; добавлен тест на конфигурацию между третью и самим таймаутом, которую прежняя проверка
пропускала.

`config.go:258` (godoc) и `README:420` против `config.go:469-471`: валидация проверяет только
`HeartbeatInterval < SessionTimeout`. Конфигурация 40s/45s проходит `Validate()` без ошибок,
нарушая заявленное правило втрое.

**Чем грозит.** Одна потерянная heartbeat выбрасывает из группы → ребаланс-шторм, а пользователь
уверен, что раз валидация прошла — ограничение соблюдено.

**Исправление.** Либо `3*HeartbeatInterval > SessionTimeout` в валидацию, либо переформулировать
документацию как рекомендацию. *Проверено вручную.*

## У6 [УМЕРЕННО] Цель `fmt` в Makefile документирована как проверка, но переписывает исходники

**Статус: закрыто волной 1.** Цель `fmt` зовёт `gofmt -l` и падает со списком файлов, ничего не
переписывая; переписывает по-прежнему только `lint-fix`.

`Makefile:31-33`. `go fmt ./...` — это `gofmt -l -w`: он **записывает** файлы и печатает имена.
`test -z` ловит непустой вывод и падает, но файлы уже изменены. `all: fmt vet lint test` (`:12`) —
`make all` на неотформатированном дереве сначала перепишет файлы, потом упадёт. `help` при этом
печатает «Check gofmt formatting», обещая read-only.

**Исправление:** `@test -z "$$(gofmt -l .)" || (gofmt -l . && exit 1)`. *Проверено вручную.*

## У7 [УМЕРЕННО] `consumer.go` — 1035 строк, три слоя в одном файле

Втрое больше следующего исходника (`config.go` 579, `producer.go` 359). Совмещает публичный API,
метрики, партиционную машинерию и ребаланс. **Тесты этот разрез уже провели**
(`consumer_lifecycle_test.go`, `consumer_retry_test.go`, `consumer_poison_test.go`,
`consumer_test.go`), а исходник — нет. `Start`/`Stop`/`AddHandler` — то, что читает потребитель, —
тонут между `resolveFailure` и `awaitWorkers`.

**Предлагаемый перенос без изменения кода** (один пакет, API не ломается):

| файл | ~строк | содержимое |
|---|---|---|
| `consumer.go` | 350 | публичные типы, конструктор, `AddHandler`, `Start`, `Stop`, `topics`, `handler`, `watchContext` |
| `consumer_worker.go` | 400 | `workerKey`, `partitionWorker`, `dispatch`, `worker`, `runPartitionWorker`, `processRecord`, `runHandler`, `callHandler`, `resolveFailure`, `poison`, `countMessage` |
| `consumer_rebalance.go` | 200 | `onPartitions*`, `rebalanceBudget`, `stopWorkers`, `stopAllWorkers`, `awaitWorkers` |
| `consumer_metrics.go` | 90 | `consumerMetrics`, `newConsumerMetrics`, статусные константы |

**Отдельно: `encoding/` как подпакет обоснован, трогать не надо.** 127 строк мало, но пакет
листовой (импортирует только `google/uuid`), и это позволяет продюсеру на другой стороне провода
кодировать ключи, не притаскивая Kafka-клиент. Обоснование записано в пакетном комментарии. Перенос
в корень — ухудшение.

## Мелочи

* **Бинарники линтеров не переустанавливаются при обновлении `tools/go.mod`** — `Makefile:4-8`,
  файловая цель без предпосылок. Поднятие версии локально не подхватится: `make lint` зелёный
  локально, CI (где `.tools/` всегда пустой) красный. →
  `$(TOOLS_DIR)/golangci-lint: tools/go.mod tools/go.sum`.
* **`coverage.out` / `coverage.html` не в `.gitignore` и не убираются `clean`** — `Makefile:19-21`,
  `:48-49`. После `make test-cover` висят untracked; `git add -A` затащит их в коммит.
* **README не отмечает, что `Brokers` и `ClientID` — env-required** — `README:352-355` против
  `config.go:51,53`. В колонке «По умолчанию» стоит «—» и больше ничего, хотя `cleanenv.ReadEnv`
  завершится ошибкой. Для сравнения, у `Consumer.Group` env-required нет, и README честно пишет
  «Обязателен». Отказ громкий и понятный, поэтому мелочь.
* **Нет LICENSE, нет раздела License в README** — модуль объявлен как
  `github.com/alfzs/kafkax/v2`, публичный путь. Для внутреннего потребления безвредно; при
  публикации отсутствие лицензии блокирует pkg.go.dev.
* **`contextcheck` — единственный молча выключенный линтер** — `.golangci.yml:13-102`: конфиг
  образцовый, у каждого из ~30 отключённых есть причина, а `contextcheck` не фигурирует ни в
  `enable`, ни в `disable`. Для пакета, где контексты перекладываются вручную
  (`context.WithoutCancel` в `consumer.go:515,521`, `trace.ContextWithSpan` `:575`,
  `rebalanceBudget` `:870`), это ровно тот класс проверок. Родственный `containedctx` включён и уже
  поймал одно место.

## Проверено и в порядке

* **`RetryBackoff`:** пример, с которого начинался прошлый аудит, исправлен и согласован в трёх
  местах — `config.go:207-210`, `constantBackoff` (`opts.go:292-299`), `README:400`.
* **Все шесть Go-блоков README компилируются** — собраны отдельным модулем с `replace` на
  репозиторий, `go build ./...` = exit 0. Ни одного расхождения в именах полей, типах и сигнатурах.
* **Имена метрик:** все девять в `README:323-333` и `doc.go:109-112` совпадают с литералами
  посимвольно.
* **Полный список полей конфигурации в обе стороны:** корень 4/4, SASL 3/3, TLS 6/6, Producer 13/13,
  Consumer 15/15, программные поля 5/5. Лишних в README нет, забытых тоже.
* **Все 41 значение по умолчанию сверены README ↔ `env-default`. Расхождений ноль.**
* **`example.env`:** все пять переменных существуют в `config.go` с точно такими именами.
* **Современный Go по делу:** `slices.Sorted(maps.Keys)`, `slices.Backward` в `Chain`,
  `context.WithoutCancel`, `errors.Join`, встроенный `min()`, `for range` по каналу. Единственный
  дженерик — `record[T]` в `otel.go`, схлопывает десять однотипных регистраций. Дженериков ради
  дженериков нет. `any` вместо `interface{}` везде.
* **Идиоматичность:** `error` последним везде, `context.Context` первым везде, `else` после
  `return` не встречается, именованные возвраты только там, где их требует `defer`/`recover`.
  Конструкторы возвращают конкретные типы, интерфейсы объявлены для потребителя.
* **Config-структура вместо функциональных опций оправдана:** конфигурация приходит из окружения
  через cleanenv-теги, функциональные опции с env-загрузкой не сочетаются. Escape hatch есть
  (`ExtraOpts`, `TLSConfig`).
* **Размеры функций:** самая длинная `processRecord` — 75 строк и линейна. `funlen` и `nestif`
  включены и молчат.
* **Все 26 `//nolint` несут объяснение**; `nolintlint` с `require-explanation`/`require-specific`
  это обеспечивает. Три в продакшн-коде, каждая с содержательной причиной.
* **`go.mod`:** все девять прямых зависимостей реально импортируются. `kfake`/`kmsg` только
  тестами — нормально, с pruning Go 1.17+ они не попадут в сборку потребителя. Линтеры вынесены в
  отдельный модуль — верно.
* **CI ↔ Makefile:** мёртвых шагов нет. Отсутствие отдельного шага `fmt` не дыра — форматтеры
  (`gofmt`, `gofumpt` с extra-rules, `gci`) объявлены в секции `formatters` `.golangci.yml`.
* **`.golangci.yml`:** `errcheck` с `check-type-assertions` и `check-blank` (в комментарии
  зафиксировано, какой класс ошибок ловил `check-blank`), `errorlint`, `nilerr`, `forcetypeassert`,
  `containedctx`, `fatcontext`, `sloglint`, `modernize`, `exhaustive`, `nolintlint`.
